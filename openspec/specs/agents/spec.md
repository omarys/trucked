## Purpose

## Entities

### StoryMemory

> `src/Trucked.Story/StoryTypes.fs`

Represents a fragment of repressed trauma or memory unlocked through narrative progression.

**Properties:**

| Name | Type | Description |
|------|------|-------------|
| Id | string | Unique identifier for the memory fragment |
| Name | string | Human-readable name of the memory fragment, formatted from the ID |
| Description | string | Narrative text describing the memory fragment |
| UnlockedAt | DateTime | UTC timestamp when the memory was unlocked |

**Relationships:**

- belongs to NarrativeState (A memory is stored within a narrative state's memory bank)

### NarrativeState

> `src/Trucked.Story/StoryTypes.fs`

Represents the ongoing state of narrative progression, story positioning, and unlocked memory
fragments.

**Properties:**

| Name | Type | Description |
|------|------|-------------|
| Player | Combatant | The player character combatant instance |
| Memories | Map<string, StoryMemory> | Map of unlocked memories keyed by their identifier |
| CurrentKnot | string | The current Ink story knot or narrative chapter identifier |
| IsGameOver | bool | Indicates whether the narrative or game session has ended |

**Relationships:**

- has-one Combatant (References the player combatant associated with the narrative)
- has-many StoryMemory (Maintains a collection of unlocked story memories)

### ArchetypeInfo

> `src/Trucked.Cli/Archetypes.fs`

Represents a predefined character archetype specification used as a template to configure and
instantiate combatants for simulations.

**Properties:**

| Name | Type | Description |
|------|------|-------------|
| Name | string | Display name of the archetype |
| Tier | CombatTier | Progression tier of the combatant (e.g., Novice, Veteran, Master, GrandMaster) |
| Discipline | CombatMode | Primary combat discipline or mode (e.g., Physical or Arcane) |
| Description | string | Textual overview of the archetype's combat behavior, equipment, and specialization |
| Factory | unit -> Combatant | Factory function producing an instantiated Combatant |

**Relationships:**

- produces Combatant (Factory creates an instantiated Combatant configured for the archetype)

### Combatant

> `src/Trucked.Cli/Archetypes.fs`

Represents a combat entity participating in simulations, configured with identity, attributes,
armor, and stats.

**Properties:**

| Name | Type | Description |
|------|------|-------------|
| Id | CombatantId | Unique identifier for the combatant |
| Name | string | Display name of the combatant |
| HP | int | Hit points / health capacity of the combatant |
| Morale | int | Morale pool of the combatant |
| Armor | ArmorIntegrity | Armor integrity protecting the combatant |
| StatBlock | StatBlock | Collection of combat stat values assigned to the combatant |

**Relationships:**

- instantiated-by ArchetypeInfo (Created and initialized by archetype factory functions or custom builder)

## Requirements

### Requirement: StoryMemoryValidation

The system SHALL validate StoryMemory according to these rules:
- Id uniquely identifies the memory fragment in the narrative state
- Name must be derived from Id by replacing underscores with spaces

#### Scenario: UnlockKnownMemoryFragment
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** A recognized memory identifier such as 'rain_and_headlights'
- **WHEN** AwardMemory is invoked on NarrativeState
- **THEN** A StoryMemory is created with predefined narrative description and current UTC timestamp

#### Scenario: UnlockUnrecognizedMemoryFragment
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** An unrecognized memory identifier
- **WHEN** AwardMemory is invoked on NarrativeState
- **THEN** A StoryMemory is created with fallback description 'Memory fragment: <id>'

### Requirement: NarrativeStateValidation

The system SHALL validate NarrativeState according to these rules:
- Initial state must start with CurrentKnot set to 'waking'
- Initial state must have an empty Memories map
- Initial state must have IsGameOver set to false

#### Scenario: InitializeNarrativeState
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** A valid player Combatant
- **WHEN** NarrativeState.Create is called with the player
- **THEN** NarrativeState is created with knot 'waking', empty memories, and IsGameOver false

#### Scenario: AwardMemoryToNarrativeBank
- **GIVEN** A NarrativeState without the memory 'prepared_mind'
- **WHEN** AwardMemory is called with 'prepared_mind'
- **THEN** A new NarrativeState is returned with the memory mapped under key 'prepared_mind'

#### Scenario: CheckExistenceOfUnlockedMemory
- **GIVEN** A NarrativeState that has been awarded 'shattered_windshield'
- **WHEN** HasMemory is called with 'shattered_windshield'
- **THEN** The result is true

### Requirement: ArchetypeInfoValidation

The system SHALL validate ArchetypeInfo according to these rules:
- Archetype lookup by name matches case-insensitively by exact name first, falling back to substring matching
- Novice tier archetypes are level 1 combatants with no preparations
- Grandmaster tier archetypes represent level 200 combatants with 6 preparations and specialization bonuses

#### Scenario: FindArchetypeByExactName
- **GIVEN** A registered roster containing an archetype named 'Veteran Fighter'
- **WHEN** findByName is called with 'Veteran Fighter' or 'veteran fighter'
- **THEN** Returns Some containing the matching ArchetypeInfo

#### Scenario: FindArchetypeByPartialName
- **GIVEN** A registered roster containing archetypes matching substring 'fighter' without an exact match
- **WHEN** findByName is called with 'fighter'
- **THEN** Returns Some containing the first ArchetypeInfo whose name contains 'fighter'

#### Scenario: FindArchetypeWithNoMatch
- **GIVEN** A registered roster containing archetypes
- **WHEN** findByName is called with a name that matches neither exact nor substring
- **THEN** Returns None

#### Scenario: InstantiateCombatantFromArchetype
- **GIVEN** An ArchetypeInfo template
- **WHEN** The Factory function is invoked
- **THEN** A configured Combatant instance corresponding to the archetype is returned

### Requirement: CombatantValidation

The system SHALL validate Combatant according to these rules:
- Custom combatants are initialized with a newly generated CombatantId, a StatBlock from provided stat pairs, and an ArmorIntegrity instance

#### Scenario: CreateCustomCombatant
<!-- openlore-test: tags=smoke (auto) -->
- **GIVEN** A name, hp, morale, armor value, and a sequence of StatId and integer pairs
- **WHEN** createCustom is called with the given parameters
- **THEN** A Combatant is created with a newly generated CombatantId, the constructed StatBlock, and Armor set
to the given armor integrity
